# MiMo-V2-Omni：统一感知与代理行动的全模态模型

## 1. 论文信息与模型定位

- **原始来源**：[Xiaomi MiMo-V2-Omni](https://mimo.xiaomi.com/mimo-v2-omni)，Xiaomi MiMo Team，**2026-03-18**。
- **本文依据**：2026-10-08 保存的官方发布页，包括正文、内联 JavaScript 的原始评测数据及页面图表。原页面没有正式 Figure/Table 编号。
- **模型定位**：把图像、视频、音频和文本感知连接到代理工具调用和界面定位，重点为“看、听、判断下一步行动”的统一模型。

这是一份官方发布材料，没有公开完整网络配置和训练 recipe。开头出现的机器人、车辆等场景用于阐述愿景，不能当作模型已经在相应实体系统通过验证的事实。

## 2. 快速概览

官方说明专用图像、视频和音频编码器接入共享骨干，联合处理多种感知输入；输出原生支持结构化工具调用、函数执行接口及 UI grounding。模型强调理解当前场景并推理未来事件，再形成行动决策。

六项感知结果覆盖音频、图像与视频。音频 MMAU-Pro 为 **69.4**、BigBench Audio 为 **94.0**；图像 MMMU-Pro **76.8**、CharXiv RQ **80.1**；视频 Video-MME **85.3**、FutureOmni **66.7**。不同任务上的相对优势不一致，并未同时超过所有对照。

官网还展示七小时播客摘要、行车视频风险分析、电影音画理解、跨平台购物和制作并上传视频。前三类是感知输出，后两类结合 OpenClaw 运行环境执行工作流；这些示例与标准基准要分别阅读。

## 3. 整体架构

可确认的是 **多种专用编码器→共享骨干→推理及结构化行动输出**。它把感知和代理目标放在共同模型中，而非只发布几个互不相关的转录和看图服务。但本材料没有给出编码器名称、骨干层数、参数规模、稠密/MoE 形式、tokenizer、音视频同步编码或输出解码器配置。

“支持结构化工具调用”表示模型可以产生工具请求，外部环境实际执行函数并返回状态。官网两项代理演示以 OpenClaw 为运行框架：它负责浏览器、文件系统与终端，MiMo 提供感知、推理和选择动作。完成任务是模型与工具环境共同作用，不能把浏览器状态变化写成模型权重自身执行的动作。

音视频联合输入能为声音、说话人与事件提供共同上下文，但官方没有披露时间窗口如何对齐、音频是否压缩、长输入的状态管理策略。七小时示例自称不分块、无中间摘要、单次处理；这一公开陈述不等于所有十小时音频都已在统一测试中证明无退化。

## 4. 核心创新与数学原理

第一项技术主张是感知和行动共同建模。模型不只描述现在的画面，还要推理可能的后续事件和应采取的动作。官网表示从训练开始就学习这些目标，然而没有给出未来预测标签、损失函数及目标配比，本文不自行补上世界模型公式或动作策略优化式。

第二项是统一输入和行动接口，让同一模型在视觉理解、长音频与代理任务之间工作。它的价值需通过跨任务结果评估；官网“全模态没有能力代价”的说法没有同骨干、同数据、同计算预算的单模态消融支持，因此只能视为作者主张。

从系统角度，可把演示理解为循环：观察状态，选择工具与参数，工具执行，返回新状态，再继续判断。这个循环有真实反馈，能让模型从字体错误或非标准网页输入中恢复，但并不自动消除规划、感知和执行错误。来源未披露循环奖励函数、动作序列监督或每步定位误差的数学模型。

本材料没有网络结构原图，以下使用的是官网原评测图表，不能将其视为训练算法图。

## 5. 数据构建与处理

官网提到创新的视频预训练及未来推理能力，但没有公开预训练语料数量、图文/视频/音频比例、长音频来源、时序标注、过滤和去重。支持的模态不能直接转换成训练集配方。

五项演示使用不同材料：行车记录视频、电影片段、单段七小时播客，以及浏览器/终端任务。电影示例将家庭声音与画面中的动作联系起来，展示音画语义解释；播客示例给出结构化摘要。本文核对的是官网展示内容，并未独立播放七小时原音频或人工核验所有时间戳。

行车示例输出潜在并线、遮挡和行人风险，文中“制动已启动”等语句是**模型生成的文本**，来源没有提供车辆执行日志、碰撞指标或驾驶闭环。它说明风险分析用例，不证明可直接控制自动驾驶。

网页中的数值由 `perceptionData`、`agenticData`、`codeData` 动态绘图，HTML 正文提取时不会自动包含这些数字。本文逐项读取原始图表数据与图例，不根据营销文案推算指标。

## 6. 训练流程与目标

公开资料明确统一感知与行动的训练定位，并提到视频预训练；没有披露各阶段样本量、冻结、学习率、优化器、批大小、硬件数量、SFT 或强化学习配方。本文不把 MiMo-V2-Flash 或其他家族模型的训练方法搬入 Omni。

公开输出包括感知解答、未来事件推理与结构化工具请求，但这些任务究竟用什么标签和奖励训练，在该来源中仍不清楚。七小时音频的处理方式是发布示例的推理配置，不能当作所有训练样本都具有七小时时长。

视频创作演示用程序合成音效并渲染四个场景，产出十五秒、1080p 视频，原文报告渲染约三十秒。不能把它解释为模型原生输出图像/音频/视频 token，也不能把渲染时间当成包括浏览器发布的总工作流延迟。

未来方向明确包括实时流感知、以小时或天维持目标、多模型协作及机器人动作。官网将它们列为尚待推进的方向，因此当前模型能力不能按这些未来目标描述为已经实现。

## 7. 实验设置与主要结果

**配图状态**：三幅原评测图由官方页面内联 JavaScript 与 HTML/CSS 动态生成，未提供独立原始图片。未取得静态截图；下面保留官方图表入口，数字按固定快照的原始 HTML 绘图数据核验。本文没有用品牌标识或自行重绘图代替。

[官网原始感知评测动态图](https://mimo.xiaomi.com/mimo-v2-omni#perception-grid)

**读图**：橙色为 MiMo-V2-Omni，其余依图例对应 Claude Opus 4.6、GPT-5.2、Gemini 3 Pro/Flash；缺失的柱表示该任务未列出该对照，并非零分。原图覆盖音频、图像和视频三类任务。

| 感知任务 | MiMo-V2-Omni | Gemini 3 Pro | Gemini 3 Flash |
|---|---:|---:|---:|
| MMAU-Pro | 69.4 | 65.0 | 67.0 |
| BigBench Audio | 94.0 | 91.2 | 99.2 |
| MMMU-Pro | 76.8 | 81.0 | 81.2 |
| CharXiv RQ | 80.1 | 81.4 | 80.3 |
| Video-MME | 85.3 | 88.4 | 76.7 |
| FutureOmni | 66.7 | 60.3 | 62.9 |

MMAU-Pro、FutureOmni 高于两个 Gemini 对照，BigBench Audio 高于 Pro 但低于 Flash；图像两项均低于两种 Gemini。MMMU-Pro/CharXiv 高于 Opus 4.6 的 **73.9/77.4**，低于 GPT-5.2 的 **79.5/82.1**。视频结果不能笼统称为都超过 Gemini Pro，Video-MME 为 85.3 对 88.4。

发布页没有说明 Video-MME 是否使用字幕、抽帧数、图像分辨率或工具预算，也没有给出所有模型的版本日期和统一推理协议，因此不与其他论文里不同预算的数字直接拼接排名。

[官网原始多模态代理评测动态图](https://mimo.xiaomi.com/mimo-v2-omni#agentic-grid)

**读图**：三项任务都是代理工作流，结果随环境与工具设置变化。它们与感知图的单项理解指标不是同一含义。

| 代理任务 | MiMo-V2-Omni | Opus 4.6 | GPT-5.2 | Gemini 3 Pro |
|---|---:|---:|---:|---:|
| MM-BrowserComp | 52.0 | 59.3 | 47.4 | 37.2 |
| OmniGAIA | 49.8 | 59.7 | 58.3 | 62.5 |
| Claw Eval | 54.8 | 66.3 | 59.6 | 51.9 |

MM-BrowserComp 高于 GPT-5.2 和 Gemini Pro，但低于 Opus；OmniGAIA 低于这三项对照，也低于 Gemini Flash 的 **51.7**；Claw Eval 高于 Gemini Pro，但低于 GPT 和 Opus。不能将选择性优势写成三项都领先。

[官网原始代码与文本代理评测动态图](https://mimo.xiaomi.com/mimo-v2-omni#code-grid)

**读图**：GDPVal 的单位是 **Elo**，其他两项是任务分数，不能直接平均。PinchBench 标注 avg.，其具体重复次数和统计区间未在发布页披露。

MiMo 的 SWE-Bench Verified 为 **74.8**，低于 Opus 80.8、GPT-5.2 80.0、Gemini Pro 76.2、Flash 78.0；GDPVal 为 **1410 Elo**，高于两个 Gemini 的 1201/1191，低于 GPT 1462 和 Opus 1606；PinchBench 为 **81.2**，略低于 Opus 81.5，高于其余对照。

官网购物与视频上传是单次成功演示，没有任务全集、成功/失败样本量和统一预算。它们支持模型可以在特定环境执行长工作流，尚不足以证明零干预可稳定迁移到任意网站或实体设备。最有依据的结论是统一模型具备广泛感知和代理能力，同时保留了明确的任务强弱差异；网络结构、训练 recipe 和超长输入退化曲线仍未公开。

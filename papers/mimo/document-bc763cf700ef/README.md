## 2. 快速概览

MiMo-V2.5 在 MiMo-V2-Flash 的混合滑动窗口语言主干上加入自研视觉与音频编码器，经轻量 projector 把不同模态映射进语言表征空间。架构原图还画出 LM Head 与 MTP Block，体现常规语言输出和多 token 预测模块，但正文没有提供 MTP 的预测深度、训练损失或实际推理加速数字。

能力重点包括日常编码与工具任务、图表和文档理解、视频及多模态交互。相对 MiMo-V2-Omni，官方网页中 Claw-Eval Multimodal 从 15.8 提升到 23.8，HR-Bench 4k 从 83.3 到 88.5，VideoHolmes 从 59.5 到 64.0。与外部模型比较则有优势也有落后：MMMU-Pro 77.9 低于表中的 Gemini 3 Pro 81.0 和 GPT-5.4 81.2；多模态 Claw-Eval 与 Sonnet 4.6 同为 23.8，却低于 Opus 4.6 的 24.8 和 GPT-5.4 的 25.7。因此“处于前沿水平”应理解为具体任务上的接近表现，不能写成所有多模态任务第一。

## 3. 整体架构

![MiMo-V2.5官方架构原图的忠实PNG渲染](figures/official-architecture-preview.png)

[下载官方 SVG 原图](figures/official-architecture.svg)。图中的蓝色、绿色、黄色分别表示音频、视觉与文本 token。音频路径从波形经过 Audio Tokenizer、Local Transformer 和 Audio Projector；视觉路径由图像或视频帧进入 MiMo ViT，再经过 Visual Projector；文本则形成文本 token。这些表征共同进入 MiMo Hybrid-SWA Backbone，上方连接 LM Head 和 MTP Block。

原图明确指出音频与视觉不是先转换成文字再输入模型，也不是所有原始波形和像素直接进入无编码器主干。两类编码器均由团队内部预训练，语言骨干继承 MiMo-V2-Flash 的混合滑动窗口注意力。但“继承架构”并未公开 V2.5 的精确层序列、窗口宽度、全局注意力比例或 KV cache 方案，本文不将旧版本所有细节直接移植到新版本。

视觉帧和音频共同出现在原图中，表明可联合处理视频相关感知信息；图没有给出采帧率、时间戳编码、音视频对齐粒度、每图 token 或最长独立音频秒数。图中一串颜色块是示意，不能靠数块得出实际 token 数。

## 4. 核心创新与数学原理

本发布说明没有编号公式。它公开的是结构组合和能力提升，而没有公开新的训练损失推导。为理解跨模态投影，可以将已披露路径概括为：

\[
z_v=P_v(E_v(I_{1:T})),\qquad
z_a=P_a(E_a(a)),\qquad
z_t=\operatorname{Embed}(x),
\]

然后让统一主干处理这些表征。这里 \(E_v\) 对应 MiMo ViT，\(E_a\) 概括音频 tokenizer 与局部 Transformer；\(P_v,P_a\) 是各自 projector。公式是本文对原图的抽象，不表示原文公布了它们的张量形状、精确拼接次序或投影层数。

混合滑动窗口注意力通过局部邻域减少部分层的长序列配对成本。标准局部注意力可写为 \(\operatorname{softmax}(Q_tK_{\mathcal N_t}^{\top}/\sqrt d)V_{\mathcal N_t}\)，其中 \(\mathcal N_t\) 是窗口中的可见位置。固定窗口 \(W\) 下，局部层注意力成本约为 \(O(NWd)\)；若混合结构包含全局层，仍有全局的二次项。发布页没有给出混合比例，因此不能把全模型推理成本断言为严格线性。

稀疏专家把总容量与每 token 激活量分离。15B/310B 约为 **4.84%**，这是激活与总参数之比；全部专家仍要存储，通信、注意力和共享模块也有计算，不能按此比例直接换算显存或服务成本。页面未提供路由专家总数、top-k、共享专家配置及负载平衡方法。

训练末段提到 **RL 与 MOPD**，但正文没有展开 MOPD 的具体目标或方程。尽管它链接到既有研究，不能仅凭缩写在 V2.5 介绍中补写一个未核对的偏好蒸馏配方。MTP 也只在图中出现，本文不据图证明具体加速比。

## 5. 数据构建与处理

官方披露了总体 **48T token** 训练量，并用“多样文本语料”“高质量跨模态数据”描述数据来源类型。自研视觉与音频编码器有各自预训练，但其数据集、授权范围、模态配比、合成数据比例、采帧和重采样方法均未在此说明。48T 是公布的总体训练口径，不等于 48T 个独立文本 token，也不能据此分配到五个训练阶段。

网页的性能图由 JavaScript 根据具名模型数组和数值数组生成。本文读取这些真实数据，并保留准确的对比对象，而没有根据柱形高度估数。例如编码数组中的 `pro` 明确叫 **MiMo-V2-Pro**；正文某处却说在内部编码测试中“匹配 MiMo-V2.5-Pro 且半价”。两个名称不相同，所以不能把编码数组里的 71.5 自动认作 V2.5-Pro 的分数。

原网页的静态配图主要是架构 SVG，评测图是动态生成元素而非可直接保存的官方 PNG。这里保留真正原图，结果采用可追溯的 Markdown 表摘录，不把自行绘制的图宣称为官方原图。各数据均按快照版本解释，不假定页面从首发以来没有更新。

## 6. 训练流程与目标

发布页列出五个阶段：

1. **文本预训练**：在多样语料上建立语言主干。
2. **Projector warmup**：把音频与视觉投影模块对齐到语言模型。
3. **大规模多模态预训练**：使用高质量跨模态数据共同训练感知和语言能力。
4. **监督微调与 Agent 后训练**：上下文逐步从 32K 扩展至 256K，再到 1M。
5. **RL 与 MOPD**：进一步强化感知、推理与 Agent 能力。

正文没有给出各阶段冻结哪些模块、学习率、优化器、损失权重、batch size、token 消耗及训练轮次。“projector warmup”说明了对齐目标，不能由名称断言视觉、音频编码器和语言模型全部冻结；后续的 RL 也未指明使用 PPO、GRPO 或何种奖励模型。

FP8 E4M3 Mixed 是公开权重表中的精度标记，不能据此直接认定所有参数、激活、梯度与优化器状态都以 FP8 训练。Token Plan 里 1x/2x 的变化属于发布日期的计费计划，正文没有给出统一的各任务实际消耗、基础货币价格或墙钟时间；“高 token 效率”因此不能用模型参数比单独证明。

## 7. 实验设置与主要结果

下表从原 HTML 的 `multimodalData` 摘录，不依赖动态柱状图估值。各分数的样本数、完整 harness、采样温度和置信区间未在发布页披露。

| 多模态基准 | MiMo-V2.5 | MiMo-V2-Omni | 原页外部参照 | 观察 |
|---|---:|---:|---|---|
| CharXiv RQ | 81.0 | 80.1 | Gemini 3 Pro 81.4 | 高于 Omni 0.9，略低于 Gemini |
| MMMU-Pro | 77.9 | 76.8 | Gemini 3 Pro 81.0；GPT-5.4 81.2 | 不是表中最高 |
| HR-Bench 4k | 88.5 | 83.3 | Gemini 3 Pro 86.4 | 高分辨率理解优势较明显 |
| OmniDocBench | 87.2 | 86.7 | GPT-5.4 89.0 | 低于表中 GPT 对照；不将数值改成编辑距离 |
| Claw-Eval Multimodal | 23.8 | 15.8 | Sonnet 4.6 23.8；Opus 4.6 24.8；GPT-5.4 25.7 | 与 Sonnet 持平，较 Omni 提高 8.0 |
| Video-MME | 87.7 | 85.3 | Gemini 3 Pro 88.4 | 接近但略低于 Gemini |
| DailyOmni | 83.5 | 80.5 | Gemini 3 Pro 84.2 | 较 Omni 提高 3.0 |
| VideoHolmes | 64.0 | 59.5 | Gemini 3 Pro 64.2 | 复杂视频推理接近外部参照 |

页面并未说明视频测试是否统一使用字幕和相同帧预算，也没有在这里给出独立音频识别或语音翻译指标。具备原生音频理解的结构，不能代替音频专项实验结果。

| 编码 / Agent 基准 | MiMo-V2.5 | MiMo-V2-Pro（原数组命名） | 部分外部对照 |
|---|---:|---:|---|
| 内部 MiMo Coding Bench | 71.8 | 71.5 | Opus 4.6 77.1；Gemini 3.1 Pro 67.8 |

正文称 Claw-Eval general subset 为 62.3，网页数组标为 Text，此处保留两种原始表述，不能把它当成多模态子集 23.8 的同一分数。内部编码集还缺少公开任务清单和独立复现信息，“缩小前沿差距”不等于所有公开编码评测领先。网页柱图使用非零基线，例如多项多模态图从 60 起、编码图从 40 起，柱高差异不可直接当成倍数提升。

这份说明支持一个清晰结论：MiMo-V2.5 将独立视觉、音频编码器与长上下文稀疏语言主干结合，在多项感知与工具任务上优于家族旧版本。它仍缺少完整训练配方和受控消融，无法仅据发布页量化 48T 数据、RL、MOPD、MTP 分别带来的贡献。本文没有运行模型或复现这些结果。

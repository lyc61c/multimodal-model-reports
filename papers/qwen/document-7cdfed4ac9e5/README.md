# Qwen3.5：原生多模态、线性注意力与稀疏专家

## 1. 论文信息与模型定位

目录收录的标题是 **Qwen3.5: Towards Native Multimodal Agents**，原链接为 [Qwen 官方发布博客](https://qwen.ai/blog?id=qwen3.5)。本条目前恢复并逐段核验的材料是 [Qwen3.5-397B-A17B 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-397B-A17B/blob/main/README.md)，缓存版本为 2026-10-08 的官方来源快照。以下内容以模型卡为依据；模型卡中的引用将工作记为 Qwen Team、2026 年 2 月。它没有给出完整论文式实验协议，也不能把这一张模型卡等同于家族全部型号的技术报告。

介绍对象是经过预训练和后训练的 **397B 总参数、17B 激活参数**版本。它将视觉编码器接入因果语言模型，支持图像、视频与文本任务，强调原生多模态融合、工具使用以及可切换的思考模式。397B 是权重规模，17B 是单个 token 激活的参数规模；后者不能用来估算完整模型的权重存储成本。托管的 Qwen3.5-Plus 与开放权重模型也有不同的服务配置，应分开理解。

## 2. 快速概览

模型卡公开的主要信息可以归纳为四点：视觉与语言在早期共同训练；45 个 Gated DeltaNet 层和 15 个完整注意力层交替组成 60 层网络；每层使用稀疏 MoE；长上下文与多 token 预测服务于推理效率。模型卡同时声称覆盖 201 种语言和方言，并使用大规模智能体强化学习环境。这里的环境规模和多模态训练效率是官方描述，材料没有提供足以复算吞吐量、训练成本或环境独立性的统计口径。

## 3. 整体架构

模型卡给出的语言主干隐藏维度为 4096，词表大小为 248320，层数为 60。网络布局为 15 次重复以下结构：三个“Gated DeltaNet → MoE”层，接一个“Gated Attention → MoE”层。这样多数层通过线性注意力处理长序列，间隔插入完整注意力层以维持直接访问上下文的能力。两类层不是两个互不相干的模型，而是同一主干内的交替模块。

DeltaNet 分支有 64 个 value 头、16 个 query/key 头，头维度为 128；完整注意力分支有 32 个 query 头、2 个 key/value 头，头维度为 256。完整注意力使用 64 维 RoPE，因此不能把它描述成全部头维度均施加旋转位置编码。MoE 有 512 个专家，每次激活 10 个路由专家和 1 个共享专家，专家中间维度为 1024。共享专家持续提供公共变换，路由专家随输入选择，二者共同构成稀疏前馈计算。

视觉信息经视觉编码器进入语言主干。模型卡将训练描述为 early fusion，但没有披露视觉编码器的层数、参数量、完整分辨率策略、patch 合并和视觉 token 数。因而不能将 Qwen2.5-VL 的窗口配置或旧版 Qwen-VL 的 256 查询压缩器直接移植到这里。

原生上下文长度为 **262144**，模型卡给出通过 YaRN 扩展至约 1010000 的配置示例。扩展示例的 factor 为 4、RoPE theta 为 10000000，包含交错 M-RoPE 和部分旋转位置编码配置。扩展能力、原生训练长度和托管服务默认长度是三个不同概念；Qwen3.5-Plus 的默认百万上下文不意味着开放权重版本原生配置也为百万。

## 4. 核心创新与数学原理

第一项机制是混合注意力。标准因果自注意力可写为 \(\operatorname{softmax}(QK^\top/\sqrt d+M)V\)，其中 \(M\) 阻止读取未来 token，序列较长时显式注意力矩阵开销较大。线性注意力通过递推状态减少对全部历史位置逐一计算的依赖。Gated DeltaNet 进一步以门控和增量更新控制信息保留及修正。以上是理解模块名称的数学背景，**模型卡没有提供本版本 DeltaNet 的具体更新公式、门参数化或稳定性消融**，因此这里不补写一个看似精确却未经来源确认的递推式。

第二项是稀疏专家。可用示意表达式理解其计算：

\[
h'=E_{\rm shared}(h)+\sum_{i\in \operatorname{TopK}(r(h))}w_i(h)E_i(h).
\]

这里 \(r(h)\) 表示路由评分，\(E_i\) 为专家，\(w_i\) 为被选专家权重。本式是解释性抽象，原模型卡没有规定这些权重的归一化方式、路由损失或共享分支系数。它说明为何模型可以拥有 397B 总参数而只激活约 17B：路由选择减少当前 token 的计算，但未被选中的权重仍属于模型。

第三项是多 token 预测。模型卡说明采用 multi-token prediction，可为推测解码提供后续 token 草稿。它未公开训练中预测几个位置、各位置损失系数、草稿接受率等细节。示例中的 vLLM 两个推测 token，以及 SGLang 的 NEXTN 配置，是推理引擎选项，不能反推训练目标。草稿仍须由目标模型验证，实际收益取决于接受率和服务负载。

第四项是原生多模态与智能体后训练。早期融合意在让语言和视觉能力共同形成，工具调用则让模型在信息不足时采取外部动作。但材料没有公开可还原的数据配方或强化学习算法，不能把“智能体 RL”自动写成使用 GRPO、PPO 或特定奖励函数。

## 6. 训练流程与目标

模型卡明确这不是仅预训练的基础模型，而是经过 **pretraining 与 post-training** 的版本，具备默认思考模式及非思考模式。思考模式默认开启，可通过聊天模板中的 `enable_thinking=False` 关闭；卡片说明不支持旧式软切换 `/think`、`/no_think`。这些是使用行为和模板约定，不是损失函数。

对因果语言模型而言，可用条件生成交叉熵理解基本学习问题：\(\mathcal L_{\rm CE}=-\sum_t\log p_\theta(y_t\mid y_{<t},x)\)，其中 \(x\) 可包含图像、视频和文本上下文。这个式子仅解释生成训练的通常形式；材料没有披露本版本如何对视觉 token、思考过程或工具轨迹设置损失掩码，也没有公开 MTP 与主损失的组合权重。

后训练描述涉及思考、非思考及智能体强化学习，但没有提供 SFT 样本数、偏好对数量、优化算法、奖励定义和冻结策略。学习率、batch size、训练步数、GPU 型号与数量同样未披露。模型卡中的 temperature、top-p、top-k、最大输出长度以及推测解码参数均是推理设置，不能填入训练超参数表。

## 7. 实验设置与主要结果

下面选取模型卡的实际数据，视觉任务对照列为 Qwen3-VL-235B-A22B；分数照录来源，未重新运行模型。

| 任务 | Qwen3-VL-235B-A22B | Qwen3.5-397B-A17B | 阅读限制 |
|---|---:|---:|---|
| MMMU | 80.6 | 85.0 | GPT-5.2 为 86.7、Gemini-3 Pro 为 87.2 |
| MathVision | 74.6 | 88.6 | 提示格式选择有模型间差异 |
| OmniDocBench 1.5 | 84.5 | 90.8 | 模型卡没有完整解释分数聚合定义 |
| OCRBench | 87.5 | 93.1 | OCR 基准分数，不等于实际文档全流程成功率 |
| Video-MME，含字幕 | 83.8 | 87.5 | Gemini-3 Pro 为 88.4 |
| Video-MME，无字幕 | 79.0 | 83.7 | GPT-5.2 为 85.8、Gemini-3 Pro 为 87.7 |
| OSWorld | 38.1 | 62.2 | Claude-4.5 Opus 为 66.3、Kimi-K2.5 为 63.3 |

提升并非所有对照上的全面领先。例如 MMMU、无字幕 Video-MME 和 OSWorld 仍有更高对照结果。工具条件尤其重要：BabyVision 记为 **52.3（with CI）/43.3（without CI）**，V* 记为 **95.8（with CI）/91.1（without CI）**；CI 指代码解释器条件，两者不能合并成一个无需工具的成绩。

搜索任务 BrowseComp 为 **69.0（simple fold）/78.6（discard all）**，对应不同上下文管理策略。模型卡说明搜索智能体在 256K 阈值后处理早期工具响应；这种策略参与了整套系统的成绩。表头没有授权把更高值解释成纯模型闭卷能力。MathVision 使用要求 boxed 答案的提示，而部分对照采用有无格式要求中的较高值，也影响严格公平比较。

语言任务中，GPQA 为 88.4、IFBench 为 76.5、BFCL-V4 为 72.9、SWE-bench Verified 为 76.4。这些展示语言推理、指令遵循、工具与代码能力，却不直接证明视觉架构某一模块的因果贡献。官方“Best Practices”建议多数任务最大输出 32768，数学和编程可使用 81920，但没有给出所有表项逐一一致的预算、重复试验方差或完整提示。本文因此将成绩视为官方报告结果，而不把发布模型卡当成足以独立复现训练与评测的完整技术论文。
